# Upgrading a product operator to v0.13.0

This guide is for a downstream product operator (hdfs, hive, kafka, trino, …) moving onto
`github.com/zncdatadev/operator-go` v0.13.0. It covers every breaking change in the release, ordered
by how the breakage reaches you:

1. [**Compile-time breaks**](#1-compile-time-breaks) — `go build` fails, with the exact replacement
   for each removed symbol.
2. [**Runtime and manifest breaks**](#2-runtime-and-manifest-breaks) — it compiles, but a CRD, a
   manifest or a generated file has to change.
3. [**Silent behaviour changes**](#3-silent-behaviour-changes) — nothing fails and nothing is
   logged; you must check these yourself.

Then a [worked example](#4-worked-example-migrating-an-extension) of the extension migration (the
largest edit most products will make) and a [checklist](#5-checklist).

## Before you start

```sh
go get github.com/zncdatadev/operator-go@v0.13.0
make generate      # controller-gen must emit DeepCopy() for your CR — see 1.1
go build ./... && go vet ./...
```

Work top to bottom: §1.1 (the CR contract) unblocks §1.2, and §1.3 (extensions) is easiest once the
CR type compiles again. Almost every break in §1 is a compiler error naming the exact site; the two
exceptions are called out by name in §3.

## 1. Compile-time breaks

### 1.1 The cluster CR contract

`common.ClusterInterface` shrank from twelve methods to `client.Object` plus two:

```go
type ClusterInterface interface {
    client.Object // sigs.k8s.io/controller-runtime/pkg/client

    GetSpec() *v1alpha1.GenericClusterSpec
    GetStatus() *v1alpha1.GenericClusterStatus
}
```

| Removed | Replacement |
|---|---|
| `cr.SetStatus(s)` | mutate through the pointer: `*cr.GetStatus() = *s`, or preferably set fields on `cr.GetStatus()` directly (that is what the framework does, which is why product-specific status fields survive a cycle) |
| `cr.GetRuntimeObject()` | `cr` itself — it is a `client.Object` |
| `cr.DeepCopyCluster()` | `cr.DeepCopy()` (generated by controller-gen) |
| `cr.GetObjectMeta()` | `&cr.ObjectMeta`, or the `metav1.Object` accessors from the embedded `client.Object` |
| `cr.GetScheme()` | `mgr.GetScheme()`, or `GenericReconcilerConfig.Scheme` |
| `common.ClusterObject` (embeddable helper) | `metav1.TypeMeta \`json:",inline"\`` + `metav1.ObjectMeta \`json:"metadata,omitempty"\`` |
| `GetName`/`GetNamespace`/`GetUID`/`GetLabels`/`GetAnnotations` declared on the CR | delete the hand-written methods; they come from the embedded `metav1.ObjectMeta` |

Steps for the CR type:

1. Delete `SetStatus`, `GetObjectMeta`, `GetScheme`, `GetUID`, `GetRuntimeObject` and
   `DeepCopyCluster`. Keep `GetSpec` and `GetStatus`.
2. Drop the imports that came with them — usually `k8s.io/apimachinery/pkg/runtime`,
   `k8s.io/apimachinery/pkg/types` and (unless used elsewhere in the file)
   `github.com/zncdatadev/operator-go/pkg/common`.
3. Confirm the CR embeds `metav1.TypeMeta` and `metav1.ObjectMeta`, is marked
   `+kubebuilder:object:root=true`, and run `make generate` so controller-gen emits
   `DeepCopy() *YourCluster` and `DeepCopyObject()`. Nothing here is hand-written.
4. Confirm the CR is registered with the scheme (`SchemeBuilder.Register(&YourCluster{},
   &YourClusterList{})`). The reconciler now reads the fetched object into the CR itself, so an
   unregistered type fails at `client.Get` with `no kind is registered for the type`.

The flagship example went from eight hand-written interface methods to two; see
`examples/trino-operator/api/v1alpha1/trinocluster_types.go`.

> A binary that reconciled two CR types by wrapping one product's stored object in another's
> wrapper type no longer works. Each CR type needs its own CRD and scheme registration.

### 1.2 The reconciler's type parameter

`GenericReconciler`, `GenericReconcilerConfig` and `NewGenericReconciler` are constrained by the new
`common.ClusterResource[CR]` instead of `common.ClusterInterface`:

```go
type ClusterResource[T ClusterInterface] interface {
    ClusterInterface
    DeepCopy() T
}

type GenericReconcilerConfig[CR common.ClusterResource[CR]] struct { /* … */ }
```

`DeepCopy() T` is what `make generate` already produces, so if §1.1 step 3 is done there is nothing
to write. The reconciler needs it because `new(T)` is unavailable for a pointer type parameter: the
fetch path materialises the object it reads into by deep-copying
`GenericReconcilerConfig.Prototype`.

Everything else generic over a CR — `RoleGroupHandler[CR]`, `ClusterExtension[CR]`,
`ExtensionRegistry[CR]`, `testutil.MockRoleGroupHandlerFor[CR]` — is still constrained by plain
`common.ClusterInterface`. Do not over-apply the change.

`reconciler.EnsureDiscoveryConfigMap` can no longer return
`discovery configmap owner %q: runtime object %T is not a client.Object`; that failure mode is now a
compile-time impossibility. Delete any handling of it.

### 1.3 The extension registry

The registry is generic over the CR type and owned by the reconciler.

| Removed | Replacement |
|---|---|
| `common.NewExtensionRegistry()` | `common.NewExtensionRegistry[*MyCluster]()` — the type argument cannot be inferred from a no-argument call |
| `*common.ExtensionRegistry` (type) | `*common.ExtensionRegistry[*MyCluster]` in every declaration, field and parameter |
| `common.GetExtensionRegistry()` | nothing — there is no process-wide registry. Build one per CR type and pass it as `GenericReconcilerConfig.ExtensionRegistry` |
| `common.ResetExtensionRegistry()` | `registry.Clear()` on the instance you own (it still empties in place, so a reconciler that captured the pointer observes the reset) |
| `common.AsClusterExtension[*MyCluster](ext)` and `AsRoleExtension` / `AsRoleGroupExtension` | nothing — pass `ext` directly; extensions declare the concrete CR type in their hook signatures |
| `RegisterClusterExtensionWithPriority(ext, p)` | `RegisterClusterExtension(ext, common.WithPriority(p))` |
| `RegisterClusterExtensionWithOptions(ext, o1, o2)` | `RegisterClusterExtension(ext, o1, o2)` |
| `cr common.ClusterInterface` in a hook signature | the concrete CR, e.g. `cr *hdfsv1alpha1.HdfsCluster` |
| `var _ common.ClusterExtension[common.ClusterInterface] = &MyExt{}` | `var _ common.ClusterExtension[*MyCluster] = &MyExt{}` |
| `common.PrioritizedExtension`, `common.NoOpExtension` | removed — the registry orders solely by the `WithPriority` registration option, so a `Priority()` method was silently ignored |

Same substitutions for the Role and RoleGroup levels. `WithPriority`, `WithStopOnError`, the
priority constants and the ordering semantics (highest priority first, registration order as the
tiebreak) are unchanged.

`GenericReconcilerConfig.ExtensionRegistry` is now `*common.ExtensionRegistry[CR]`, so one registry
instance can no longer be shared between reconcilers of two different CR types — that is a compile
error, and it is the point of the change. A binary managing several products builds one registry per
type.

See [§4](#4-worked-example-migrating-an-extension) for the full before/after.

### 1.4 The config format contract

| Removed / changed | Replacement |
|---|---|
| `config.ConfigFormat` | `config.ConfigMarshaler` (required, `Marshal` only). If the value's `Unmarshal` is also called, use `config.ConfigUnmarshaler`, or an inline `interface { config.ConfigMarshaler; config.ConfigUnmarshaler }` |
| `RegisterFormat(ext string, format ConfigFormat)` | `RegisterFormat(ext string, format ConfigMarshaler)` — passing an adapter still works; passing a variable typed `ConfigFormat` does not |
| `NewConfigGenerator(format ConfigFormat)` | `NewConfigGenerator(format ConfigMarshaler)` |
| `config.GetFormat(t).Unmarshal(s)` | `config.NewConfigGeneratorWithType(t).Parse(s)`, or `config.NewXMLAdapter().Unmarshal(s)` when you want the concrete adapter. `GetFormat` returns `ConfigMarshaler`, which has no `Unmarshal` |
| reaching into the adapter map to parse by file name | `generator.Parse(filename, content) (map[string]string, error)` |
| string matching on config errors | `errors.Is(err, config.ErrNoFormat)`; `var e *config.UnsupportedParseError; errors.As(err, &e)` then `e.File` / `e.Format` |

**Your own adapters need no change**: an adapter implementing both methods satisfies both
interfaces. If you wrote an `Unmarshal` purely to satisfy the old contract and nothing reads that
format back, delete it — that is the point of the split.

Error strings changed (they now name the file and the format), so anything matching on them must
move to the typed checks above:

- `MultiFormatConfigGenerator.Generate`/`GenerateFiles`:
  `failed to generate config file "x.env" with the .env (*config.EnvAdapter) format: …`
  (previously an emit failure was reported as a parse failure).
- Adapters no longer wrap through `common.ConfigParseError`. Emit failures read
  `failed to serialize <format> configuration: …`; read failures keep
  `failed to parse <format> configuration: …`. The XML adapter's label changed from `XML` to `xml`.
- A nil format returns the sentinel `config.ErrNoFormat` instead of a fresh `fmt.Errorf`.
- `ConfigMapBuilder.WithMergedConfig` names the ConfigMap:
  `failed to generate config files for ConfigMap ns/name: …`.

### 1.5 Everything else

| Removed / changed | Replacement |
|---|---|
| `security.ListenerVolume(volumeName, secretClass string, format SecretFormat)` | `security.ListenerVolume(volumeName, secretClass, listenerVolumeName string, format SecretFormat)` — `listenerVolumeName` is the name of the pod volume mounting the listener, which the secret-operator resolves to that listener's addresses. It is required (see §2) |
| `listener.VolumeRegistration.WithScope`, `listener.ListenerScope`, `ListenerScopeNode`, `ListenerScopeCluster`, `ListenerScopeAnnotation` | nothing — the listener-operator never read the annotation. Declare a volume with `listener.NewVolume(name, class)` and optionally `.WithListenerName(name)`; a registration with neither a class nor a listener name is rejected |
| `sidecar.SidecarConfig.MainContainerName` | `sidecar.FindContainer(podSpec, name)` inside the provider; the primary container's name is set through `reconciler.BaseRoleGroupHandler.MainContainerName` / `SetRoleMainContainerName` |
| `sidecar.FindMainContainer(podSpec, name)` | `sidecar.FindContainer(podSpec, name)` (or `sidecar.FindContainerIndex`) |
| `RoleGroupCleaner.Cleanup(ctx, namespace, clusterName, spec, status) error` | `Cleanup(ctx, namespace, clusterName, spec, status, ownerUID types.UID, crAnnotations map[string]string) (time.Duration, error)` — the duration is the earliest pending wakeup (0 when nothing is pending). Only affects code driving the cleaner directly; `GenericReconciler` does this for you |
| `commonsv1alpha1.ZKConfig` | `DependencyResolver.ValidateZKConfig` accepts the connection string; a `*ZKConfig` was silently accepted whatever it contained |
| `commonsv1alpha1.GracefulShutdownSpec` | `RoleGroupConfigSpec.GracefulShutdownTimeout` (a duration string) |
| `commonsv1alpha1.StorageResourceSpec` | `ResourcesSpec.Storage` |
| `authenticationv1alpha1.ResponseType` (`ResponseTypeCode`, `ResponseTypeToken`) | nothing — it typed no CRD field in any group |
| `common.HealthCheckResult` | nothing — `ServiceHealthCheck.CheckHealthy` reports `(bool, error)` and never produced or consumed the struct |
| `common.RoleInterface`, `common.RoleInfo`, `common.RoleGroupInfo` | nothing — the reconciler iterates `spec.Roles` directly, and role group configuration reaches handlers through `reconciler.RoleGroupBuildContext` |
| `testutil.ClusterWrapper`, `testutil.WrapMockCluster(x)` | `*testutil.MockCluster` and `x`; drop the optional scheme argument (there is no `GetScheme` to feed). `testutil.MockRoleGroupHandler` is now `MockRoleGroupHandlerFor[*MockCluster]` |

## 2. Runtime and manifest breaks

These compile. They need a CRD re-apply, a manifest edit, or a check of generated content.

**Re-apply the shared CRDs.** `S3ConnectionStatus`, `S3BucketStatus` and `DatabaseConnectionStatus`
serialize their conditions under `.status.conditions` (previously `.status.condition`), so `kubectl`
and `kstatus` can see them. Anything reading `.status.condition` — a JSONPath in a script, a
kustomize health check, a dependent operator — must be updated, and whatever existing objects hold
under the old field is orphaned: the operator owning those resources writes the new field from now
on.

**Required scalars no longer carry `omitempty`.** Zero values are always emitted (`"host": ""`,
`"className": ""`, `"credentials": null`) so a request omitting them is rejected by the required
check rather than passing silently. Golden files and manifest diffs will show the added keys.

**`ListenerSpec.publishNotReadyAddresses` is a `*bool`.** The wire format is unchanged; a Go client
constructing a `ListenerSpec` must use `ptr.To(false)` to express false, and should read it through
`spec.GetPublishNotReadyAddresses()` (nil ⇒ false).

**The JMX exporter config moved.** `sidecar.JMXExporterConfigMountPath` is now
`/kubedoop/mount/config/jmx-exporter` instead of `/opt/jmx_exporter`, because a ConfigMap volume
replaces the whole directory it mounts over — the old path shadowed the jar the container executes
(`sidecar.JMXExporterJarPath`, `/opt/jmx_exporter/jmx_prometheus_httpserver.jar`). Any product
config, image or documentation naming the old path must be updated. Pods restart on the next
reconcile.

**Invalid CSI wiring now panics at registration instead of producing an unusable volume.**
`security.ListenerVolume` with an empty `listenerVolumeName` panics, as does any named scope key
(`service=`, `listener-volume=`) registered without a value through
`SecretVolumeRegistration.WithScope` or `SecretProvisioner.Register` — a bare `listener-volume`
entry carries no name for the CSI driver to resolve. Unknown scope keys still pass; the scope
vocabulary belongs to the secret-operator. `WithMountBasePath` (on both `SecretProvisioner` and
`ListenerProvisioner`) panics on a relative path — it would compose into a container `mountPath` the
API server rejects — and ignores an empty argument, keeping the default. The panic fires wherever
the product constructs the provisioner, so where it surfaces depends on your code.

**`PDBBuilder.Build()` panics when no selector was set.** A PodDisruptionBudget with an empty
selector matches every pod in the namespace and blocks their eviction; the API server accepts it, so
this could only be caught here.

**Generated config file content changes.** Expect a one-time diff in the role group ConfigMap (and
a pod restart if the workload carries the restarter label):

- `.env`: values are double-quoted unless every character is in `[A-Za-z0-9_@%+=:,./-]`. This is a
  security fix — sourcing a file with an unquoted `;`/`&`/`|`/`$()` value executed it. Update
  fixtures; do not restore the old behaviour.
- `.env` parsing: a single-quoted value reads back literally, so `KEY='a\nb'` yields four characters,
  not a newline. Switch to double quotes if you relied on the expansion.
- XML: carriage returns travel as `&#13;`, and a key or value containing C0 control characters
  (other than tab/LF/CR) or non-UTF-8 bytes is now an **error** naming the key instead of an
  unparseable document. Sanitize upstream, or move that entry to a format that can carry it.
- `.properties`: `\uXXXX` escapes (surrogate pairs included) decode, and the indentation of a
  continuation line is dropped, as `java.util.Properties` does. Keys escape `#`/`!`, values escape
  their edge whitespace.
- YAML: a duplicate key is an error instead of last-one-wins. De-duplicate the input.
- Logger names from the CRD are escaped per target format, so a name containing a space, separator,
  quote or line break no longer re-shapes the file.
- The generated Python logging file is no longer named `logging.py` (it shadowed the standard
  library module whenever the config directory ended up on `sys.path`).

**Listener PVC templates no longer carry `listeners.kubedoop.dev/scope`.** These are ephemeral
volumes in the pod template, so this is a rolling update, not an immutable-field conflict.

**Audit overlapping `RegisterFormat` calls.** When a file name matches several registered
extensions (e.g. both `.properties` and `server.properties`), the **longest** now wins
deterministically. If you were unknowingly relying on the generic adapter winning some of the time,
either drop the specific registration or accept the now-stable — possibly different — output.

## 3. Silent behaviour changes

Nothing fails to compile and nothing is logged. Check each one.

### 3.1 A reconciler with no `ExtensionRegistry` configured runs ZERO hooks

This is the one migration mistake with no compiler or runtime signal. There is no process-wide
registry any more, so a reconciler whose `GenericReconcilerConfig.ExtensionRegistry` is nil runs an
empty registry: every `PreReconcile`, `PostReconcile` and `OnReconcileError` hook is a no-op. An
operator that used to register through `common.GetExtensionRegistry()` without wiring the config
field will start up cleanly, reconcile cleanly, and never run its extensions.

Grep your `main.go` for `GenericReconcilerConfig` and confirm every one carries
`ExtensionRegistry: registry,`.

### 3.2 A successful reconcile now requeues on the health-check interval

A successful cycle returns `ctrl.Result{RequeueAfter: …}` — `GenericReconcilerConfig.HealthCheckInterval`
(`DefaultHealthCheckInterval` = 120s when unset, negative disables the periodic wakeup), or the
earliest pending cleanup deadline when that is sooner. Previously a successful cycle returned an
empty `ctrl.Result` and the controller slept until the next watch event.

This is what makes state that produces no event converge: a product `ServiceHealthCheck` probe
result, a gray-delete grace period running out, the ordered drain of an orphaned StatefulSet.
The cost is a periodic reconcile per CR. If your product's reconcile is expensive, set
`HealthCheckInterval` explicitly rather than leaving the default.

### 3.3 Other quiet changes

- **`GetLabels()`/`GetAnnotations()` come from `metav1.ObjectMeta` and return nil when unset**, not
  an empty map. Every SDK consumer copies them into a fresh map, so framework behaviour is
  unchanged; product code that indexes or writes into the returned map needs a nil check.
- **Orphan cleanup takes several reconciles.** A removed role group is scaled to zero, drained by
  the StatefulSet controller, then deleted, with each resource confirmed absent before the next type
  is touched. A role group no longer disappears within one reconcile, and its status entry is pruned
  only after a real deletion. A 429 anywhere in the cleaner surfaces as a `*reconciler.RateLimitError`
  and backs off instead of marking the cluster `Degraded`.
- **The status write is skipped when nothing changed**, and `SetCondition` preserves
  `LastTransitionTime` unless the status actually flips. A settled cluster stops rewriting its
  status — if you were watching `.metadata.resourceVersion` churn as a liveness signal, it is gone.
- **`podOverrides` resolve one-of collisions in favour of the override.** When an override states a
  different member of a mutually exclusive struct the framework also populates (volume sources,
  probe and lifecycle handlers, `EnvVar` value/valueFrom), the framework's member is dropped before
  the merge instead of deep-merging into an object the API server rejects. Overriding the `config`
  volume is now a supported operation. An override naming the same member still merges field by
  field.
- **Sidecars are injected in phase order**: `SidecarPhaseProducer` (10) → `SidecarPhaseDefault` (50)
  → `SidecarPhasePipeline` (90), and in name order within a phase. Vector declares `Pipeline`, so it
  is injected after the producers whose shared log volume it mounts. A provider can declare its own
  phase with `sidecar.PhasedProvider`; `RegisterWithPhase` still wins over it.
- **Sidecar provider validation is a real gate.** `SidecarManager.ValidateAll` runs before the
  StatefulSet is applied and a failure aborts the role group with a `*reconciler.ValidationError`.
  The Vector provider requires the target ConfigMap to exist *and* carry `vector.yaml`.
- **The Vector sidecar is skipped, not failed, when nothing supplies `vector.yaml`.** Implement
  `reconciler.VectorAggregatorProvider` on the CR (the framework renders the file) or
  `reconciler.VectorConfigProvider` on the handler; with neither, the framework emits a
  `VectorSidecarSkipped` warning event and moves on.
- **Objects returned by a builder no longer share state with it.** `Build()` deep-copies every map,
  slice and pointer, so mutating a built object for one role group cannot reach the builder or the
  next role group. Code that relied on that aliasing (deliberately or not) silently stops working.

## 4. Worked example: migrating an extension

Taken from `examples/trino-operator/internal/extensions/catalog_extension.go` and
`examples/trino-operator/cmd/main.go`.

### Before

```go
func (e *CatalogExtension) PreReconcile(
    ctx context.Context,
    k8sClient client.Client,
    cr common.ClusterInterface,
) error {
    logger := log.FromContext(ctx)
    logger.Info("CatalogExtension PreReconcile", "cluster", cr.GetName())

    // Cast to TrinoCluster for type-specific operations
    trinoCR, ok := cr.(*trinov1alpha1.TrinoCluster)
    if !ok {
        return fmt.Errorf("expected *TrinoCluster, got %T", cr)
    }

    if err := e.validateCatalogs(trinoCR); err != nil {
        return fmt.Errorf("catalog validation failed: %w", err)
    }
    return nil
}

var _ common.ClusterExtension[common.ClusterInterface] = &CatalogExtension{}
```

```go
// main.go
common.GetExtensionRegistry().RegisterClusterExtensionWithPriority(
    common.AsClusterExtension[*trinov1alpha1.TrinoCluster](extensions.NewCatalogExtension()),
    common.PriorityHigh,
)

reconcilerCfg := &reconciler.GenericReconcilerConfig[*trinov1alpha1.TrinoCluster]{
    // … no ExtensionRegistry field: the reconciler used the singleton
}
```

### After

```go
func (e *CatalogExtension) PreReconcile(
    ctx context.Context,
    k8sClient client.Client,
    cr *trinov1alpha1.TrinoCluster,
) error {
    logger := log.FromContext(ctx)
    logger.Info("CatalogExtension PreReconcile", "cluster", cr.Name)

    if err := e.validateCatalogs(cr); err != nil {
        return fmt.Errorf("catalog validation failed: %w", err)
    }
    return nil
}

var _ common.ClusterExtension[*trinov1alpha1.TrinoCluster] = &CatalogExtension{}
```

The entry-point type assertion is gone — structurally, not by convention: the registry is
instantiated for `*TrinoCluster`, so this hook can only ever be handed a `*TrinoCluster`. `cr.Name`
and `cr.Namespace` come from the embedded `ObjectMeta` (`cr.GetName()` still works). Status writes go
directly to the product's own fields: `cr.Status.CatalogsReady = readyCatalogs`.

Do the same for `PostReconcile` and `OnReconcileError`, and for every `RoleExtension` /
`RoleGroupExtension` (their extra `roleName` / `roleGroupName` parameters are unchanged).

```go
// main.go — one constructor per CR type, owning the registry
func newExtensionRegistry(scheme *runtime.Scheme) *common.ExtensionRegistry[*trinov1alpha1.TrinoCluster] {
    registry := common.NewExtensionRegistry[*trinov1alpha1.TrinoCluster]()

    registry.RegisterClusterExtension(extensions.NewCatalogExtension())
    registry.RegisterRoleExtension(extensions.NewHealthExtension())
    registry.RegisterClusterExtension(
        extensions.NewDiscoveryExtension(scheme),
        common.WithPriority(common.PriorityLow),
    )

    return registry
}

reconcilerCfg := &reconciler.GenericReconcilerConfig[*trinov1alpha1.TrinoCluster]{
    // …
    ExtensionRegistry: newExtensionRegistry(mgr.GetScheme()), // MANDATORY — see §3.1
}
```

In tests, replace `common.GetExtensionRegistry()` + `common.ResetExtensionRegistry()` with a per-test
instance and, where the reconciler outlives the spec, `DeferCleanup(registry.Clear)`:

```go
registry := common.NewExtensionRegistry[*trinov1alpha1.TrinoCluster]()
DeferCleanup(registry.Clear)
```

Per-test instances also make the specs safe to run in parallel.

## 5. Checklist

- [ ] `go get` the new version; `make generate`; `go build ./... && go vet ./...` until clean.
- [ ] CR type: only `GetSpec` and `GetStatus` hand-written; `TypeMeta`/`ObjectMeta` embedded;
      registered with the scheme.
- [ ] Every extension hook takes the concrete CR; every interface-satisfaction assertion
      re-instantiated; no `As*Extension` wrappers left.
- [ ] **Every `GenericReconcilerConfig` literal sets `ExtensionRegistry`** (§3.1) — grep for it.
- [ ] `ConfigFormat` replaced by `ConfigMarshaler`; emit-only adapters' unused `Unmarshal` deleted;
      error-string matching replaced by `errors.Is` / `errors.As`.
- [ ] `security.ListenerVolume` calls pass a listener volume name.
- [ ] Shared CRDs re-applied; consumers of `.status.condition` moved to `.status.conditions`.
- [ ] Product config/images referencing `/opt/jmx_exporter` for the exporter *config* updated.
- [ ] Golden files and manifest fixtures regenerated (`.env` quoting, XML `&#13;`, required scalars).
- [ ] `HealthCheckInterval` reviewed (§3.2).
- [ ] `make lint && make test`.
